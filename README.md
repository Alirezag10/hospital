# سامانه پذیرش، خدمات و ترخیص بیمارستان

این مخزن نسخهٔ کامل پروژهٔ آموزشی با PHP، Yii 2 و MySQL/MariaDB است. اجرای اصلی با Nginx انجام می‌شود. همهٔ کاربران واردشده دسترسی عملیاتی یکسان دارند.

## امکانات و گردش کار

1. بیمار را با نام، نام خانوادگی، کد ملی و موبایل ثبت کنید؛ تاریخ تولد اختیاری است.
2. در فهرست یا صفحهٔ بیمار، «ثبت پذیرش» را بزنید. بیمار در فرم پذیرش از قبل انتخاب شده است.
3. پزشک و بخش را انتخاب کنید. تاریخ پذیرش می‌تواند خالی بماند تا زمان فعلی ثبت شود.
4. در صفحهٔ پذیرش یا خلاصهٔ پرونده، «افزودن خدمت» را بزنید. پذیرش از قبل انتخاب شده است؛ خدمت و تعداد را مشخص کنید.
5. پس از ثبت خدمت، خلاصهٔ پرونده و جمع هزینه نمایش داده می‌شود. برای خدمات بیشتر، دوباره «افزودن خدمت» را بزنید.
6. «مشاهده هزینه و ترخیص» ریز خدمات و جمع مبلغ را نشان می‌دهد. توضیحات را وارد و «تأیید و ثبت ترخیص» را بزنید.
7. تاریخ و مبلغ نهایی ثبت می‌شوند، وضعیت به «ترخیص‌شده» تغییر می‌کند و خلاصهٔ پرونده نمایش داده می‌شود.

از فرم عمومی ترخیص نیز می‌توان پذیرش را انتخاب و با «مشاهده ریز هزینه» پیش‌نمایش را باز کرد. مبلغ نهایی در سرور و هنگام ثبت، دوباره از مجموع تعداد × قیمت واحد خدمات محاسبه می‌شود؛ اگر خدمات در فاصلهٔ پیش‌نمایش تا ثبت تغییر کرده باشند، مبلغ نهایی ممکن است متفاوت باشد.

قیمت واحد خدمات قبلی با تغییر تعرفه یا تعداد عوض نمی‌شود. بیمه، مالیات، تخفیف و فرانشیز وجود ندارند. ترخیص تکراری و تغییر خدمات یا پذیرش پس از ترخیص رد می‌شوند. چند پذیرش برای هر بیمار مجاز است؛ محدودیت یک پذیرش فعال در صورت پروژه اختیاری است.

## اطلاعات پایهٔ لازم

پیش از اولین پذیرش، **حداقل یک پزشک و یک بخش** لازم است. آن‌ها را از منوی «اطلاعات پایه ← پزشکان / بخش‌ها» تعریف کنید. پیش از افزودن خدمت، حداقل یک خدمت فعال در منوی «خدمات» تعریف کنید.

در نصب تازه، می‌توانید به‌جای تعریف دستی، فایل `database/demo_reference_data.sql` را فقط یک بار وارد کنید. این فایل یک پزشک، یک بخش و دو خدمت نمونه ایجاد می‌کند و بیمار یا پرونده‌ای نمی‌سازد. واردکردن این فایل اختیاری است؛ وجود دادهٔ پزشک و بخش برای پذیرش ضروری است.

## پیش‌نیازها

- PHP 8.2 یا بالاتر و افزونه‌های Yii، از جمله `pdo_mysql`، `mbstring` و `openssl`.
- Composer 2 و وابستگی‌های `app/composer.lock`.
- MySQL یا MariaDB با پشتیبانی InnoDB.
- Nginx و PHP FastCGI. مسیرهای پیش‌فرض ویندوز: `C:\nginx` و `C:\xampp\php`.

از ریشهٔ پروژه در PowerShell:

```powershell
composer --working-dir=app install
& C:\xampp\php\php.exe .\app\requirements.php
New-Item -ItemType Directory -Force .\app\runtime, .\app\web\assets
```

این پروژهٔ آموزشی در حالت توسعه اجرا می‌شود؛ `composer install` معمولی برای وابستگی‌های debug و gii استفاده کنید.

## نصب پایگاه داده در سیستم تازه

1. MySQL را روشن کنید.
2. یک دیتابیس **خالی** مانند `hospital` با collation برابر `utf8mb4_unicode_ci` بسازید.
3. همان دیتابیس را انتخاب و فقط `database/install.sql` را وارد کنید.
4. اطلاعات پایه را دستی تعریف یا `database/demo_reference_data.sql` را یک بار وارد کنید.

`install.sql` هر هشت جدول برنامه را می‌سازد. SQLهای `001_create_patients.sql` و `002_create_remaining_tables.sql` مربوط به نسخهٔ قدیمی‌اند؛ در نصب فعلی از آن‌ها استفاده نکنید.

**روی دیتابیس موجود فایل نصب یا دادهٔ نمونه را دوباره اجرا نکنید.** فایل نصب ابزار ارتقای دیتابیس نیست. برای تغییرات این نسخه نیازی به تغییر ساختار دیتابیس فعلی نیست.

## اتصال و حساب ورود

اگر فایل اتصال وجود ندارد:

```powershell
Copy-Item .\app\config\db.example.php .\app\config\db.php
```

نام دیتابیس، پورت، نام کاربری و رمز MySQL را در `app/config/db.php` تنظیم کنید. نمونه در `db.example.php` است؛ فایل موجود سیستم فعلی را بازنویسی نکنید.

برای ساخت اولین حساب در نصب تازه:

```powershell
& C:\xampp\php\php.exe .\app\yii setup/create-user operator
```

دستور رمز تولیدشده را نمایش می‌دهد. حساب موجود را تغییر نمی‌دهد. کاربران واردشده دسترسی یکسان دارند و صفحهٔ مدیریت نقش‌ها وجود ندارد. ستون `users.role` برای سازگاری با دیتابیس موجود باقی مانده است.

## اجرای Nginx

در `deploy/nginx.conf` مسیر `root` را با مسیر واقعی `app/web` هماهنگ کنید. جداکنندهٔ مسیر در Nginx `/` است. از تنظیم فعلی نسخهٔ پشتیبان بگیرید و سپس نمونه را کپی کنید:

```powershell
Copy-Item C:\nginx\conf\nginx.conf C:\nginx\conf\nginx.conf.backup
Copy-Item .\deploy\nginx.conf C:\nginx\conf\nginx.conf
```

MySQL را روشن و از ریشهٔ پروژه اجرا کنید:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Hospital.ps1
```

پنجرهٔ PHP را باز نگه دارید. اسکریپت تنظیم Nginx را تست می‌کند، آن را اجرا یا reload می‌کند و PHP FastCGI را روی `127.0.0.1:9000` اجرا می‌کند. اگر پورت 9000 اشغال باشد، نمونهٔ دوم اجرا نمی‌شود.

مسیرهای دیگر:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Hospital.ps1 -NginxDirectory C:\nginx -PhpDirectory C:\xampp\php
```

[باز کردن داشبورد](http://localhost:8080/index.php?r=site/index)

برای توقف PHP در پنجرهٔ آن `Ctrl+C` بزنید. برای توقف Nginx:

```powershell
& C:\nginx\nginx.exe -p C:\nginx\ -s quit
```

## رفع خطاهای رایج

- `502 Bad Gateway`: PHP باید روی `127.0.0.1:9000` اجرا باشد.
- خطای اتصال دیتابیس: وضعیت MySQL و مقادیر `db.php` را بررسی کنید.
- فهرست خالی پزشک یا بخش: از منوی اطلاعات پایه، حداقل یک مورد تعریف کنید.
- فهرست خالی خدمات: یک خدمت فعال از منوی خدمات بسازید.
- `ViewNotFoundException`: viewها باید در `app/views` باشند؛ نسخه‌های داخل `app/web/app` جزو ساختار برنامه نیستند.
- اشغال پورت: فرایند موجود را شناسایی کنید و نمونهٔ دوم اجرا نکنید.

## اجرای آزمون‌ها

آزمون‌ها به دیتابیس جدا نیاز دارند و `config/db.php` را نمی‌خوانند. یک دیتابیس خالی با نام `hospital_test` بسازید. نام دیتابیس آزمایشی باید با `hospital_` شروع و با `test` تمام شود.

از ریشهٔ پروژه؛ اتصال و رمز را مطابق دیتابیس آزمایشی خود تنظیم کنید:

```powershell
$env:HOSPITAL_TEST_DSN = 'mysql:host=127.0.0.1;port=3306;dbname=hospital_test'
$env:HOSPITAL_TEST_USER = 'root'
$env:HOSPITAL_TEST_PASSWORD = ''
php .\scripts\Prepare-TestDatabase.php
```

دستور آماده‌سازی فقط دیتابیس خالی را می‌پذیرد و یک بار برای هر دیتابیس لازم است. آزمون‌ها داده‌های دیتابیس آزمایشی را پاک و بازسازی می‌کنند.

سپس از پوشهٔ `app`:

```powershell
php vendor\bin\codecept build
php vendor\bin\codecept run Unit
php vendor\bin\codecept run Functional
php vendor\bin\codecept run Acceptance --env php-builtin
```

محیط `php-builtin` یک وب‌سرور موقت روی 8080 اجرا می‌کند؛ این پورت باید آزاد باشد. برای آزمون با Nginx جداگانه روی `127.0.0.1:8081` و ورودی `index-test.php`، از `--env nginx` استفاده کنید. این ورودی و دیتابیس آزمایشی برای آزمون محلی‌اند؛ تنظیم تحویل `deploy/nginx.conf` فقط `index.php` را اجرا می‌کند.

## وضعیت نسخهٔ اصلاح‌شده

در ۵ اکتبر ۲۰۲۶، آزمون‌های واحد، کاربردی و HTTP از طریق Nginx روی دیتابیس موقت جدا اجرا شدند. جزئیات تغییرات، نتایج آزمون‌ها و محدودهٔ تأیید در `output/report/WORK_REPORT.md` آمده است. چک‌لیست تحویل در `DELIVERY_CHECKLIST.md` است. نصب و اجرای نهایی باید با مسیرها و دیتابیس سیستم مقصد هماهنگ شود.
